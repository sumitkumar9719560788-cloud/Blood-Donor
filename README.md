# LifeLink

LifeLink is a full-stack blood donation and emergency blood-bank discovery platform.

## Project structure

- Root `src/` – React + Vite frontend for blood search, donor registration, emergency requests, and dashboard views.
- `backend/` – Express + TypeScript API using MongoDB and Mongoose.

## Frontend

The frontend connects to the API configured by `VITE_API_URL` (defaults to `http://localhost:5000/api`). It includes:

- Home landing page
- Blood search page
- Donor search page
- Emergency request form
- Dashboard page
- Login and registration screens
- Opt-in donor search and request responses

Run it:

```bash
npm install
copy .env.example .env
npm run dev
```

## Backend

The backend contains:

- Mongoose models for users, donors, blood banks, blood requests, and reports
- Express routes for auth, donors, blood banks, requests, and admin
- JWT auth and role protection middleware
- Zod validation and rate limiting
- Seed script for demo data

Setup:

```bash
cd backend
npm install
copy .env.example .env
```

Set `JWT_SECRET` in `.env` to a random secret with at least 32 characters, and set `DATABASE_URL` to your MongoDB connection string. The local example expects MongoDB running as a replica set named `rs0`; MongoDB Atlas is already configured as a replica set. Then run:

```bash
npm run seed
npm run dev
```

The backend connects to MongoDB at startup using Mongoose. Collection names are kept compatible with the prior database layout.

To enable password recovery, configure `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, and `SMTP_FROM` in the backend environment. Until configured, the password reset endpoint returns an unavailable response and does not generate recovery links.

For a fresh production database, create the first administrator from the API service shell with `ADMIN_NAME`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` set, then run `npm run bootstrap:admin`. The command refuses to run if an administrator already exists; it never opens public admin registration.

The former PostgreSQL migration files are not used by MongoDB. If you have existing PostgreSQL data, migrate it separately before switching the application to MongoDB.

The API is available at `http://localhost:5000/api`. The seed script creates demonstration users with non-production passwords; change or remove these before any deployment.

## API overview

- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`
- `GET /api/banks?city=&bloodGroup=`
- `GET /api/donors/nearby?city=&bloodGroup=`, `POST /api/donors`
- `GET /api/donors/me` (authenticated donor profile)
- `POST /api/requests`, `GET /api/requests`, `GET /api/requests/opportunities`, `GET /api/requests/assigned`, `POST /api/requests/:id/respond`
- `GET /api/admin/stats`, `GET /api/admin/reports`, `GET /api/admin/users`, `PATCH /api/admin/users/:id/role`, `PATCH /api/admin/users/:id/active`, `GET /api/admin/requests`
- `GET /api/admin/donors/pending`, `PATCH /api/admin/donors/:id/verification`
- `GET /api/admin/banks/pending`, `POST /api/admin/banks`, `PATCH /api/admin/banks/:id/verification`
- `POST /api/reports`
- `GET /api/health`

## Notes

- Donor contact data is never returned by public search. Requests are shown to matching opted-in donors only after the requester consents to sharing.
- Donor profiles require administrator verification before appearing in search or receiving request opportunities. Profile edits return the profile to pending review.
- Donor responses change a request to `CONTACTING`; the app does not send SMS, call emergency services, or guarantee blood availability.
- `render.yaml` defines a Render Node API and static frontend. To deploy, push the repository to GitHub, create a Render Blueprint from it, then provide `DATABASE_URL` when prompted. The API secret is generated by Render. Keep the service names `lifelink-api` and `lifelink-web` or update both URL settings in the blueprint if you rename them. Set SMTP environment values in the API service to enable password recovery.
- Render's free web services and static sites are available for hobby use, but free web services can sleep while idle and are not recommended for production. See [Render's free plan limitations](https://render.com/docs/free). The Atlas IP access list must allow the API service's outbound IP ranges; avoid opening access to every IP unless you knowingly accept that exposure. [Render outbound IPs](https://render.com/docs/outbound-ip-addresses), [Atlas IP access lists](https://www.mongodb.com/docs/atlas/security/ip-access-list/).
- For deployment, set frontend `VITE_API_URL` to the API URL and backend `CLIENT_URL`, `DATABASE_URL` (MongoDB Atlas), and a unique `JWT_SECRET` in the hosting environment. Build the backend with `npm run build` and start it with `npm start`; build the frontend with `npm run build`.
- Replace `.env` secrets before using in production.
- The emergency and donor features clearly indicate they are verification-based and should not be treated as emergency medical service dispatch systems.
